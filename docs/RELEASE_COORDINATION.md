# Release Coordination: parqtel-oss ↔ homebrew-tap

How the [`parqtel-oss` formula](../Formula/parqtel-oss.rb) stays in lock-step with [`parqtel/parqtel-oss`](https://github.com/parqtel/parqtel-oss) releases.

## TL;DR

| Step | Trigger | Outcome |
| --- | --- | --- |
| 1 | `parqtel/parqtel-oss` tag `v*` is pushed | GitHub creates the upstream release |
| 2 | `repository_dispatch` (optional, see below) **OR** `schedule` in this tap | `build-tarballs.yml` builds 4 binaries |
| 3 | `build-tarballs.yml` `publish-release` job | Tap release `v<version>` with 4 tarballs + sha256s |
| 4 | `update-formula.yml` polls / receives dispatch | PR opens against `main` bumping `version` + 4 sha256s |
| 5 | `audit.yml` | Validates install + test → green |
| 6 | Maintainer merges | `brew update && brew upgrade parqtel-oss` works for users |

## Bootstrapping v0.1.0

The v0.1.0 release of parqtel/parqtel-oss was the first one; this tap didn't have a `v0.1.0` release yet. The maintainer ran `build-tarballs.yml` once with `version: 0.1.0` (workflow_dispatch) to produce the v0.1.0 tap release, then `update-formula.yml` once with `version: 0.1.0` to open the initial PR. From v0.2.0 onward, the daily schedule in both workflows keeps things current.

## Optional: zero-touch coordination

Add the following to [`parqtel-oss/.github/workflows/release.yml`](https://github.com/parqtel/parqtel-oss/blob/main/.github/workflows/release.yml) (one new job after `github-release`):

```yaml
  notify-homebrew-tap:
    name: Notify homebrew-tap
    runs-on: ubuntu-latest
    needs: github-release
    steps:
      - name: Trigger homebrew-tap build
        uses: peter-evans/repository-dispatch@v3
        with:
          token: ${{ secrets.HOMEBREW_TAP_DISPATCH_TOKEN }}
          repository: parqtel/homebrew-tap
          event-type: parqtel-oss-release
          client-payload: |
            {
              "version": "${{ needs.docker-publish.outputs.version }}",
              "ref":     "${{ github.ref_name }}"
            }
```

`secrets.HOMEBREW_TAP_DISPATCH_TOKEN` must be a PAT in the `parqtel` org with `repo` scope. Once added, every `v*` tag push to parqtel-oss fires `build-tarballs.yml` (via `repository_dispatch`), which in turn fires `update-formula.yml`, and the maintainer only merges the resulting PR.

## Manual fallback

If the webhook is broken, the maintainer runs both workflows manually with the new version number. The schedule (twice daily for `update-formula.yml`, once daily for `build-tarballs.yml`) is a safety net.

## Versioning rules

- The formula's `version` is always the upstream tag without the leading `v` (`0.2.0`, not `v0.2.0`).
- The tap release tag is `v<version>` (matches upstream's convention so users browsing this tap's releases see a familiar shape).
- If a formula change is required between upstream releases (e.g. a Homebrew deprecation), bump the formula's `revision` (e.g. `revision 1`), not the `version`.

## What lives where

| Artifact | Lives in | Pushed by |
| --- | --- | --- |
| `parqtel-oss` source tarball | `parqtel/parqtel-oss` (auto-generated by GitHub for every tag) | GitHub |
| `parqtel-oss` per-platform binaries | `parqtel/parqtel-oss/releases/tag/v*` (intended) **OR** `parqtel/homebrew-tap/releases/tag/v*` (this tap, until upstream CI is stable) | upstream release.yml **OR** this tap's build-tarballs.yml |
| Homebrew formula | `parqtel/homebrew-tap/Formula/parqtel-oss.rb` | update-formula.yml (or maintainer PR) |
| Tap release notes | `parqtel/homebrew-tap/releases/tag/v*` | build-tarballs.yml `softprops/action-gh-release@v2` |
